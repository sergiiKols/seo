# Методология GEO-измерения

> Основано на разборе 17 источников, проведённом 05.08.2026.
> Файл обновлён: 02.09.2026.

---

## 1. Определения

**GEO (Generative Engine Optimization)** — оптимизация присутствия бренда в ответах генеративных моделей (LLM). Не заменяет классическое SEO, а дополняет его.

**GEO-видимость** — доля запросов, на которые модель упоминает бренд в ответе.

**LLM Visibility Score** — число 0–100, агрегированная метрика видимости.

---

## 2. Формула

### Базовая
```
LLM Visibility Score = (found_queries / total_queries) × 100
```
где `found = True` если бренд или URL обнаружен в ответе модели.

### По интентам (развесованная)
```
Score = branded × 0.2 + comparing × 0.3 + informing × 0.5
```

| Интент | Вес | Почему так |
|---|---|---|
| Branded | 0.2 | Бренд ищут по имени — должен быть. Слабый сигнал |
| Comparing | 0.3 | Модель выбирает сама — зависит от контента и внешнего следа |
| Informing | 0.5 | Самый сложный сегмент; попадание = признак качественного контента |

---

## 3. Типы запросов

### Branded
```
"Название_бренда официальный сайт"
"Название_бренда отзывы"
"Название_бренда цены"
```
**Ожидание:** 100% — бренд должен быть в ответе, если запрос корректен.
**Вес:** 20%.

### Comparing
```
"Что лучше: Название_бренда или Конкурент"
"Выбрать Название_бренда или Альтернатива"
"Рейтинг CRM: Название_бренда"
```
**Ожидание:** 40–70% — зависит от контента, отзывов, позиций в традиционном SEO.
**Вес:** 30%.

### Informing
```
"Лучшие CRM для малого бизнеса"
"Как выбрать CRM-систему"
"CRM с бесплатным тарифом"
```
**Ожидание:** 10–40% — самый сложный сегмент. Чем ýже и специфичнее, тем больше шанс.
**Вес:** 50%.

### Commercial / Transactional
```
"Скачать CRM бесплатно"
"Купить CRM с поддержкой"
```
Не приоритет для GEO — здесь модель отправляет на сайт. Но URL в ответе = бонус.

---

## 4. Что считать «найденным»

Критерий срабатывает при выполнении **любого** из условий:

1. **URL присутствует** — модель дала ссылку на `example.com` или поддомен.
2. **Название бренда присутствует** — подстрока совпадает с учётом морфологии
   (склонения не требуются, но грубые ошибки не считаются).

**Контекст цитирования не учитывается** в базовом скрипте.
Для тональности нужно разбирать текст вручную или подключать NER.

## 5. Интерпретация результатов

| Score | Уровень | Что делать |
|---|---|---|
| 0–20 | Критический | Срочно: проверить индексацию моделями, усилить внешний след (СМИ, Википедия, отраслевые справочники), добавить `llms.txt` |
| 21–40 | Слабый | Сфокусироваться на Comparing-запросах, усилить E-E-A-T, проверить наличие на отраслевых агрегаторах |
| 41–65 | Средний | Работать с Comparing и Informing, следить за динамикой ежемесячно |
| 66–80 | Хороший | Мониторить ежемесячно, не расслабляться |
| 81–100 | Отличный | Держать регулярный мониторинг, следить за контекстом (позитив/негатив) |

---

## 6. Ограничения метода

1. **Один срез ≠ динамика.** Рекомендуется повторять проверку раз в 4 недели.
2. **Модели отвечают по-разному.** Perplexity, ChatGPT и ЯндексGPT могут давать разные ответы на один запрос — это не ошибка, а свойство.
3. **Контекст не измеряется.** Позитивный/негативный контекст определяется вручную.
4. **Покрытие ограничено.** GEOrank покрывает больше моделей сразу; бесплатные API имеют лимиты.
