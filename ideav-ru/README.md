**Технически:**
- сервер `Apache/2.4.58 (Ubuntu)`, главная отдаётся статикой (`Last-Modified`,
  `ETag`, `Content-Length` — признаки готового файла, не рендера на лету);

  **126 URL** в `blog/sitemap-0.xml`;
- две карты сайта под общим индексом `sitemap-index.xml`;
- у некоторых основных страниц `lastmod` свежий (16.07.2026), у других старше
  (02.06.2026, 13.05.2026) — сайт обновляется неравномерно по разделам.

**Не проверено пока:** скорость и Core Web Vitals, состояние в Search Console /
Яндекс.Вебмастере, оптимизация блога под уточняющие вопросы (см. приём из
`ai-vidimost-2026-08.md`, п. 4.3), страницы кроме главной.

## Как применять инструментарий мастерской

Порядок по карте контуров из `../README.md`:

1. **Техническое** — частично закрыто нашим `screen-audit` и его подходом:
   можно прогнать сайт `--url` вместо файла и получить переполнение,
   `viewport`, `lang`, заголовки, консольные ошибки. `extract.mjs` из
   `dizain/design-contract` уже умеет открывать чужой сайт в браузере — по его
   образцу можно написать технический аудитор специально для SEO (индексация,
   каноникалы, `hreflang`, структура заголовков по всем 48+126 страницам).
2. **Семантика** — сравнить дерево `sitemap.xml` (по названиям страниц видно
   структуру: конструктор → решения по функциям → блог) с реальными запросами;
   пока не собрано.
3. **Содержимое** — применить тест на снятие SEO-обвязки и тест на
   заменяемость (`ai-vidimost-2026-08.md`, п. 4.1) к паре характерных страниц:
   одной продуктовой (`excel-to-app.html`) и одной из блога.
4. **Ссылки и упоминания** — не проверялось; блог с реальными кейсами
   («16 000 кликов и 333 конверсии в Директе за 2 500 рублей») — материал,
   который потенциально не пересказывается генеративным ответом (см. критерий
   из вчерашнего разбора), стоит проверить прицельно.
5–7. **Коммерческие факторы, локальное, аналитика** — не применимы или не
   проверялись; продукт не локальный бизнес, аналитика зависит от доступа к
   Search Console/Вебмастеру заказчика.

**Правило автоматизации.** Разбор сайта браузером (аудит, `extract.mjs`) —
это работа с публичной страницей, ограничение только `robots.txt` и разумная
частота запросов, само это разрешено. Если работа дойдёт до личных кабинетов
(Search Console, Яндекс.Вебмастер, рекламные кабинеты) — там действует другое
правило: см. [[automation-boundary-third-party]], автоматизировать чужие
(и свои, если это рекламная система) личные кабинеты браузером нельзя.

## Открытый вопрос

Проект заведён без конкретной задачи — по образцу мастерской, где проект-гость
начинается фактами, а не работой. Первый шаг требует ответа на два вопроса:
**что именно нужно проверить или улучшить** (полный технический аудит?
конкретная просадка? конкурентный анализ? подготовка к видимости в
генеративных ответах?) и **какой доступ есть** — только публичный сайт, или
есть Search Console / Яндекс.Вебмастер / аналитика с реальными цифрами.

Без этого дальнейшая работа рискует стать разбором ради разбора — а по правилу
мастерской годится только то, что меряется.
