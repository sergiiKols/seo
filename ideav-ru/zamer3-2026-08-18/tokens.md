## Разбор критической задачи №1 — H1

Критерий приёмки из плана: `document.querySelectorAll('h1').length === 1`
после полной загрузки, с осмысленным текстом.

**Замер (Playwright, 1440×900, `networkidle` + 4 с ожидания):**

```
h1count: 1
h1texts: ["Токены Интеграма — оплата за реальные действия"]
h1tag:  <h1 class="text-3xl md:text-4xl lg:text-5xl font-bold tracking-tight mb-4">Токены Интеграма — оплата за реальные действия</h1>
h1visible: { w: 1216, h: 96, display: "block", visibility: "visible", fontSize: "48px" }
prerenderBlock (#tk-prerender в живом DOM): false
```

**Критерий выполнен полностью.** Текст H1 — дословно:

> Токены Интеграма — оплата за реальные действия

Важная деталь механики: блок `#tk-prerender` из живого DOM по-прежнему
исчезает после гидратации (`prerenderBlock: false`) — то есть чинили не
«перестали удалять пререндер», а добавили настоящий семантический `<h1>` в
клиентский шаблон. Результат для поисковика тот же и даже лучше: H1 в сыром
HTML (`<h1 itemprop="headline">` внутри `#tk-prerender`) и H1 в
отрендеренной версии теперь **дословно совпадают** — зонд возвращает
`h1RawVsRendered: "СОВПАДАЕТ"`. Это была самая критичная находка всего
раздела; она закрыта.

Иерархия заголовков в рендере осталась осмысленной: H1 → H2 («Почему
стоимость в токенах», «Сколько токенов расходует пользователь?») → H3
(«Пример расчёта для ПЭО»).
