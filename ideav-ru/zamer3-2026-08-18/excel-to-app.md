## Критическая задача №3 — разбор с числами

Критерий приёмки из плана: «`curl` без JS отдаёт форму
(`form` / `input[type=file]` / `textarea`) и не менее ~700 слов текста».

Главная команда приёмки:

```
$ curl -sS https://ideav.ru/excel-to-app.html | grep -c -iE '<form|input[^>]+type=.file|<textarea'
3
```

Три совпадения — по одному на каждый из трёх искомых элементов (проверено
поштучно: `<form` — 1, `input…type=file` — 1, `<textarea` — 1).

| Показатель сырого HTML | 05.08 и 12.08 | 18.08 | Изменение |
|---|---|---|---|
| Байт | 14 064 | **25 746** | +11 682 (+83 %) |
| Слов видимого текста | 298 | **803** | +505 (+169 %) |
| `<h1>` | 1 | 1 | — |
| `<h2>` | 4 | **7** | +3 |
| `<h3>` | не мерили | 14 | — |
| `<form>` | **0** | **1** | форма появилась |
| `input[type=file]` | 0 | 1 | появился |
| `<textarea>` | 0 | 1 | появился |

Порог «~700 слов» превышен: **803 слова в сыром HTML против 761 слова в
отрендеренном DOM** — то есть краулер без JS получает теперь даже чуть
больше текста, чем видит браузер (в сыром HTML в подсчёт попадает часть
служебных подписей, схлопываемых при рендере). Все 7 разделов `<h2>` из
рендера присутствуют в сыром коде дословно: «Как это работает», «Что
конкретно вы получите через 45 минут», «Прекратите подстраивать бизнес под
софт», «Ваши данные — ваша собственность», «А что у зарубежных
ИИ-платформ», **«Загрузите свои таблицы»** (сама форма) и «Частые
вопросы». Раньше из них в сыром коде было только два.

Форма в сыром HTML — не заглушка, а рабочий не-JS фолбэк:

```html
<form id="excel-form" class="etl-prerender__form" action="/excel-to-app.php"
      method="post" enctype="multipart/form-data" aria-labelledby="excel-form-title">
  <input type="hidden" name="source" value="excel-to-app" />
  <label for="etl-files">…<input id="etl-files" name="files[]" type="file" multiple
      accept=".xls,.xlsx,.xlsm,.csv,.ods" />
  <label for="etl-topic">…<textarea id="etl-topic" name="topic" rows="3" …>
  <label for="etl-contact">…<input id="etl-contact" name="contact" type="text" required … />
  <button type="submit">
```

Все три поля подписаны через `label for` → `id`, форма связана с
заголовком через `aria-labelledby`. Эндпоинт `/excel-to-app.php`
существует и отвечает: `HEAD` → 405 (метод не разрешён, ждёт POST),
пустой `POST` → 403 (отбивает запрос без данных). Что он делает с реальной
отправкой, зондом не проверялось — это надо подтвердить у разработки.

Побочный нюанс: после гидратации React заменяет пререндеренную форму на
свою — id полей меняются с `etl-topic`/`etl-contact` на
`excel-topic`/`excel-contact`, а `id="excel-form"` у формы исчезает. Якорь
`/excel-to-app.html#excel-form`, который есть в самом сыром HTML, после
рендера ведёт в никуда. Мелочь, но чинится одной строкой.

Заодно выросла разметка FAQ: в JSON-LD `FAQPage` теперь **5 вопросов**
вместо 3 (добавились «Сколько стоит забрать готовое приложение?» и «Какие
ограничения на размер файлов?»).

   Последовательность соблюдена.
3. **Шапка починена на 768 px** — переполнения нет (было 1079/768).
4. **Безымянная кнопка в шапке получила текст «Ещё»** — безымянных кнопок
   на странице не осталось ни одной.
5. **Своя og-картинка** `/og/excel-to-app.png` вместо общей картинки базы
   знаний; файл реально отдаётся (200, 138 КБ).
6. **FAQ-разметка расширена** с 3 до 5 вопросов.
7. Ошибок в консоли при загрузке — 0.

## Что осталось

1. **Невидимый фокус клавиатуры на полях формы** — не тронут. Табом поля
   проходятся в правильном порядке (файл → тематика → контакт → согласие →
   ссылка на политику → отправка), но у `textarea#excel-topic`,
   `input#excel-contact` и кнопки отправки `:focus-visible` не рисует
   ничего: `outline-style: none`, `box-shadow` и цвет рамки не меняются.
   У `input[type=file]` и чекбокса кольцо есть — браузерное по умолчанию,
   то есть страница гасит фокус ровно там, где его переопределили стилями.
   Для страницы, у которой форма — единственная цель, это остаётся
   находкой первого приоритета по доступности.
2. **Остальные фразы кластера Excel** — «аналоги excel» (283),
   «автоматизация excel таблиц» (160), «преимущества электронных таблиц»
   (136), «аналог гугл таблиц» (125), «excel автоматизация процессов»
   (103) — по-прежнему 0 вхождений. Внедрённая «аналог excel» — 1 раз.
   Теперь, когда пререндер работает, любые новые формулировки попадут в
   индекс сразу — самое время дописать остальные.
3. **Перелинковка в сыром слое отстаёт от рендера.** Пререндер отдаёт
   контент и форму, но не общее меню сайта: 6 внутренних страничных ссылок
   в сыром HTML против 31 уникальной в рендере. Ссылки на
   `sravnenie-s-bitrix-amocrm.html`, `resheniya.html`,
   `konstruktor-prilozhenij.html`, `catalog-matching.html`,
   `informatsionnaya-sistema.html`, `tokens.html` краулер без JS с этой
   страницы не увидит. Раз механизм пререндера уже есть — логично
   завернуть в него и шапку с подвалом.
4. **`href="/knowledge-base"` без `.html` вернулся в сырой HTML** (в
   рендере правильный `/knowledge-base.html`). Лишний редирект, мелкая
   регрессия пререндер-слоя.
5. **Неразрывные пробелы** — 65 пропусков в сыром тексте; символов
   `&nbsp;`/U+00A0 в HTML нет вообще. Плотность та же, что была, просто
   текста стало втрое больше.
6. **Ни одного контентного изображения** — на конверсионной странице,
   которая продаёт наглядный результат, по-прежнему нет ни скриншота
   готового приложения, ни схемы.
7. **Якорь `#excel-form` ломается после гидратации** (см. выше).
8. Подтвердить у разработки, что `/excel-to-app.php` реально принимает
   отправку без JS, а не только присутствует в разметке.
