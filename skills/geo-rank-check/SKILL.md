# GEO Rank Check — видимость бренда в LLM

Вы — GEO-аналитик. Задача — проверить, присутствует ли бренд (URL, название
компании, продукт) в ответах языковых моделей на релевантные запросы.

## Запуск

Рабочая папка — корень этого скилла. Ключи — **только через переменные
окружения**, никогда аргументом команды: аргумент остаётся в истории.

### Сначала — пробный прогон (бесплатно, без сети)

    python3 scripts/geo_check.py --brand "Бренд" --url "https://site.ru" \
      --queries-file queries.csv --dry-run

### Режим direct — напрямую к провайдерам

    python3 scripts/geo_check.py --mode direct --brand "Бренд" \
      --url "https://site.ru" --queries-file queries.csv \
      --output geo-results.json --providers perplexity

Ключи: `PERPLEXITY_API_KEY`, `OPENAI_API_KEY`, `YANDEX_API_KEY`.

### Режим georank — через GEOrank

    python3 scripts/geo_check.py --mode georank --brand "Бренд" \
      --queries-file queries.csv --output geo-results.json

Ключ: `GEORANK_API_KEY`. Тарифы GEOrank — от 20 000 ₽/мес.

## Коды выхода

**Коды `10` и `20` — не сбой.** Не чинить, не повторять запуск, не менять аргументы.

| Код | Маркер | Здесь означает | Что делать |
|---|---|---|---|
| 0 | `SKILL_RESULT` | результат записан; `MENTION` / `CITATION` — доля ответов, где бренд назван и где взят как источник; `SILENT` — сколько раз взяли источником без имени; `AMBIGUOUS` — сколько спорных совпадений имени; `ERRORS` — сколько запросов упало, `RETRIES` — сколько сделано повторов | отдать результат; при `ERRORS>0` сказать, что видимость посчитана без них; при `RETRIES>0` — что повторы тоже платные |
| 1 | `SKILL_ERROR` | ошибка: неверные аргументы, нет файла, **все запросы упали** | починить один раз, если дело в аргументах или пути; иначе доложить `STAGE`, `ERROR` |
| 10 | `SKILL_NEEDS_INPUT` | не хватает ключей (`MISSING`) или запросов в файле | спросить человека **одним сообщением** всё из `MISSING`, дать ссылки из `WHERE` |
| 20 | `SKILL_NEEDS_SANCTION` | запуск потратит деньги | см. «Санкции» |

Маркер — последний блок вывода. Если вывод обрезан — один раз прочитать `--output`.

## Санкции

| Триггер | Когда срабатывает | Флаг |
|---|---|---|
| деньги | любой запуск, кроме `--dry-run`: **все провайдеры считаются платными** | `--sanction-spend` |

1. Показать человеку `WHAT` и `COST`. `WHAT` называет **и число запросов, и максимум с повторами сбоев** — согласие даётся на максимум, а не на минимум.
2. Добавить `--sanction-spend` **только после явного согласия в этом разговоре**. Молча — никогда.
3. Санкция действует на один запуск. Новый запуск — новый вопрос.
4. Записать санкцию в маршрутный лист: кто, когда, на что.

Почему все платные: бесплатный API-тариф не подтверждён первоисточником ни у одного провайдера (проверка 16.09.2026). Perplexity Sonar по вторичным источникам — $5–14 за 1 000 запросов плюс токены. Прежняя пометка «бесплатно 100/день» снята как неподтверждённая.

## Повторы временных сбоев

Запросы, упавшие на `429`, `500`, `502`, `503`, `504`, сетевой ошибке или таймауте, повторяются автоматически: экспоненциальная задержка с полным джиттером (от 1 до 30 с), при `429` с заголовком `Retry-After` — ровно столько, сколько сказал сервер. `401`, `400`, `403` не повторяются: от повтора ключ или запрос не исправятся.

- `--retries N` — повторов на запрос сверх первой попытки, по умолчанию `2`. `--retries 0` — без повторов.
- **Каждый повтор — платный запрос.** Поэтому максимум с повторами входит в санкцию, а фактическое число — в маркер (`RETRIES`).
- Повтор безопасен: запрос к модели ничего не создаёт и не меняет, кроме списания.

## APR — стабильность цитирования (`--runs`)

Один прогон LLM — не сигнал: цитирование заметно случайно. Метрика **APR
(Answer Presence Rate)** — в скольких прогонах из N бренд попал в ответ;
порог «стабильного источника» — 20% (`instruments/apr-citing-2026-09.md`).

    python3 scripts/geo_check.py --mode direct --brand "Бренд" \
      --url "https://site.ru" --queries-file queries.csv --runs 5

- `--runs N` — прогонов на каждый запрос (по умолчанию 1). Рекомендация: 5–10.
- `--base-url URL` — база OpenAI-совместимого API вместо api.openai.com: любой
  локальный или прокси-сервер (пример: `http://127.0.0.1:4096/v1`). Позволяет
  гонять APR без внешней оплаты. Оговорка: если серверная модель без веб-поиска,
  замер отвечает «упоминает ли модель бренд из памяти», а не честную
  GEO-видимость с цитатами.
- **Каждый прогон — полный платный прогон всех запросов.** Санкция считает `запросы × провайдеры × прогоны` — согласие спрашивать на это число.
- В JSON появляется блок `apr`: `mean_apr` (средний APR по запросам), `stable_queries` (запросов с APR ≥ 20%), `per_query` (APR по каждому запросу и провайдеру). Прогоны с ошибками в расчёт не входят — как и в видимости.
- В консоли: `●` — стабильный (APR ≥ 20%), `○` — случайное попадание.
- Интерпретация: запрос с APR < 20% — бренд «мигает»; стратегию по нему строить по косвенным признакам нельзя, нужно повторить замер. Запрос с APR 100% — надёжная точка отсчёта для динамики.

## Три числа вместо одного: упоминание, цитирование, спорное имя

Разбор [`instruments/seo-04-ai-tri-imeni.md`](../../instruments/seo-04-ai-tri-imeni.md).
Раньше «нас назвали» и «наш адрес попал в источники» давали один признак, и
балл складывал два разных результата. Теперь их три:

| Число | Что означает | Что с этим делать |
|---|---|---|
| **присутствие** | назвали по имени **или** взяли как источник | прежний `llm_visibility_score`, для сравнения со старыми замерами |
| **назвали по имени** | имя бренда в тексте ответа, и подтверждено, что это мы | узнаваемость: за этим человек приходит искать бренд |
| **взяли как источник** | наш домен в источниках ответа или в тексте | цитируемость: ответ наш, даже если имени нет |
| `silent_citations` | источник есть, имени нет | наш текст работает, узнаваемости ноль — просить упоминание в тексте, а не только ссылку |
| `ambiguous` | имя нашлось, подтверждения нет | **в баллы не входит**: возможно, это другой объект с тем же названием |

Знаменатель у всех трёх один — запросы без ошибки. Разные знаменатели дали бы
несравнимые проценты.

### Подтверждение объекта (`--anchors`)

Поиск имени идёт по границам слова с допуском на русское окончание до трёх букв
(«студия Идеава», «в Новосибирске» — то же слово). Этого мало: у бренда может
быть однофамилец или словарный омоним. Поэтому упоминание считается нашим,
только если рядом (±300 символов) есть подтверждающее слово:

    --anchors Новосибирск "веб-разработка" Петров

Домен из `--url` и его имя добавляются в якоря сами. Если якорей нет вовсе,
все упоминания уходят в `ambiguous`, и скрипт об этом предупреждает — чтобы
ноль в балле не читался как «нас не называют».

### Ряд замеров (`--history`)

    --history geo-history.jsonl

Прогон дописывается строкой в JSONL и сравнивается с прошлым замером того же
бренда: в консоли и в поле `trend` — изменение в процентных пунктах.

**Сравнение только при совпадении отпечатка.** `otpechatok` считается по набору
запросов и списку провайдеров; сменили набор — вместо чисел выводится причина,
почему сравнения нет. Иначе рост от смены запросов читался бы как рост
видимости. Прогон, в котором упали все запросы, в ряд не пишется.

Зачем: у автора разбираемого ролика было 4 упоминания, через год ноль, и он
ничего не менял. Одиночный замер такого дрейфа не показывает.

## Формат входного файла queries.csv

```csv
query,intent
"лучшие сервисы CRM для малого бизнеса",informing
"какой CRM выбрать для команды 10 человек",comparing
"название_бренда отзывы",branded
```

Обязательная колонка — `query`. Опционально — `intent`: informing / comparing / branded / commercial. Колонка `model` читается, но скриптом **не используется**.

## Выходной JSON

```json
{
  "brand": "Example Corp",
  "url": "https://example.com",
  "checked_at": "2026-09-16T12:00:00+00:00",
  "total_queries": 30,

  "scores": {

    "silent_citations": 4, "ambiguous": 2, "denominator": 29
  },
  "anchors": ["Новосибирск", "example.com", "example"],
  "otpechatok": "e539127e04af",
  "trend": {"comparable": true, "prev_at": "2026-08-17T12:00:00+00:00",
            "presence": -7, "mention": -10, "citation": 3},
  "mode": "direct",
  "providers": ["perplexity"],
  "results": [
    {
      "query": "лучшие сервисы CRM для малого бизнеса",
      "intent": "informing",
      "provider": "perplexity",
      "model": "sonar",
      "found": true,
      "position": 312,
      "context": "...Example Corp предлагает бесплатный тариф...",
      "citation_url": "https://example.com",
      "sentiment": "neutral",
      "error": "",
      "run": 1,
      "mention": true,
      "citation": true,
      "ambiguous": false,
      "anchor": "example.com",
      "citation_rank": 2
    }
  ],
  "summary": {
    "informing": {"total": 10, "found": 4, "errors": 0, "visibility": 40},
    "not_found_queries": ["..."],
    "silent_citations": [{"query": "...", "provider": "perplexity", "rank": 3}],
    "ambiguous_queries": [{"query": "...", "provider": "openai", "context": "..."}]
  },
  "apr": {
    "runs_per_query": 1,
    "per_query": []
  }

```

- `position` — смещение первого вхождения в тексте ответа, а не место в списке.
- `citation_rank` — место нашего адреса в списке источников ответа (1-based), если провайдер источники отдаёт. У обычного chat-completions их нет: тогда цитирование видно только по адресу в тексте.
- `anchor` — каким словом подтверждено, что назвали именно нас. Пусто и `ambiguous: true` — подтверждения не нашлось.
- `sentiment` скрипт не определяет: `neutral` при находке, `not_found` иначе. Тональность — руками.

## Как считается видимость

    видимость = найдено / (запросов − запросов с ошибкой) × 100

Запрос, упавший с ошибкой, в знаменатель **не входит**: ошибка — не ответ «бренда нет». Если упали все запросы — код `1`, а не «видимость 0».

Так считается **присутствие**. «Назвали по имени» и «взяли как источник» считаются по тому же знаменателю, каждое по своему признаку; спорные совпадения имени не попадают ни в числитель, ни в отдельный список «не найдены» — про них неизвестно, о нас ли речь.

Скрипт считает **невзвешенную** долю. Взвешенная оценка по контурам `branded × 0.2 + comparing × 0.3 + informing × 0.5` из [`references/methodology.md`](references/methodology.md) считается при интерпретации, по полю `summary`.

## Рабочий процесс

### Шаг 1. Собрать запросы

Из семантического ядра проекта отобрать:
- **branded** — с названием бренда;
- **comparing** — сравнение и выбор;
- **informing** — информационные без бренда.

Минимум 30 запросов: по 10 каждого типа.

### Шаг 2. Пробный прогон

`--dry-run` — проверить, что файл читается и запросов столько, сколько ожидалось. Бесплатно.

### Шаг 3. Боевой прогон

По кодам выхода выше. Код `20` на первом боевом запуске — норма.

### Шаг 4. Интерпретация

| LLM Visibility Score | Значение | Рекомендация |
|---|---|---|
| 0–20 | бренд практически невидим | проверить индексацию, усилить внешний след: СМИ, справочники |
| 21–40 | слабая видимость | фокус на comparing, усилить E-E-A-T |
| 41–65 | средняя | работать с comparing и informing, следить за динамикой |
| 66–80 | хорошая | мониторить ежемесячно |
| 81–100 | бренд в большинстве ответов | держать мониторинг, следить за контекстом |

### Шаг 5. Записать в проект

Файл `<проект>/geo-visibility.md`:


## Провайдеры

| Провайдер | Модель по умолчанию | Платность | Примечание |
|---|---|---|---|
| Perplexity | `sonar` | платно (закрыто по умолчанию) | лучший для поисковых запросов |
| OpenAI | `gpt-4o-mini` | платно | дополнительный источник |
| Яндекс | `yandexgpt-lite` | платно | модель и адрес API в коде не сверены с документацией Яндекса — перед первым боевым запуском проверить |
| GEOrank | — | от 20 000 ₽/мес | адрес API задан по структуре кабинета, не по документации |

Разные провайдеры дают разные ответы — это не ошибка. Для сравнения динамики держать один и тот же набор провайдеров между замерами.

## Ошибки провайдеров

| Ошибка в `error` | Причина | Решение |
|---|---|---|
| `HTTP 401` | неверный ключ | новый ключ от человека (код `10` при следующем запуске не сработает — ключ есть, но неверный: спросить явно) |
| `429 Rate limit` | лимит API, повторы исчерпаны | `--delay 3` — реже запросы |
| `network error` | сеть, повторы исчерпаны | проверить доступ к API; повторный запуск — новая санкция |
| Timeout | модель долго отвечает, повторы исчерпаны | `--timeout 60` |

## Чего не делает

- Не определяет тональность упоминания — только факт.
- Не считает взвешенную оценку по контурам — только невзвешенную долю.
- Не проверяет классическое SEO: индексацию, семантику, контент → `/root/seo/scripts/`.
- Не повторяет `401`, `400`, `403` и не повторяет больше `--retries` раз.
- Не проверяет однофамильцев без якорей: без `--anchors` и `--url` подтвердить объект нечем, все упоминания уходят в спорные.
- Не разделяет упоминание и цитирование в режиме `georank`: сервис отдаёт готовый вердикт, и своей проверки там не видно.
