# memora на SEO-участке — пробная установка

Поставлена **18.08.2026** по итогам работы над базой знаний ideav.ru.
Статус — **проба с измеримым критерием**, а не принятый инструмент.
Правило мастерской: принимается только то, что меряется.

## Зачем именно сюда

Работа 18.08 дала ровно ту боль, под которую сделано версионирование memora:

- «вместо впр excel» — 53, при перезамере 120;
- «система автоматизации отчетности» — 699 в ядре, 156 прямым замером;
- «система управления заявками» — **594 и 378 в один и тот же день**.

Числа устаревают и перемеряются, и обязаны жить с датой и методом.
Плюс 182 отклонённых кластера, ценность которых в том, чтобы всплыть через
полгода, когда кто-то снова принесёт «сводные таблицы на 228 489» как
открытие. Это цепочка версий и `digest` по теме.

**Участок не пересекается с vecmory:** там граф «запрос → ошибка → решение»,
здесь реестр измерений. Разные типы содержимого — расщепления памяти нет.

## Как устроено

| Что | Значение |
|---|---|
| Пакет | `memora-mcp` 0.3.3 (MIT), venv `/root/seo/.memora-venv` |
| База | SQLite `/root/seo/.memora/memories.db` |
| Эмбеддинги | **TF-IDF** (локально, без ключей и без затрат) |
| LLM-вызовы | **выключены** (`MEMORA_LLM_ENABLED=0`) |
| Облако | **выключено** — ни D1, ни S3, ни Cloudflare Pages |
| MCP | `claude mcp add --scope user memora-seo` — **глобально, во всех проектах** |
| Переменные | `env.sh` рядом с этим файлом |

**Почему LLM выключен.** Дедупликация и insights ходят в модель. У фабрики
`claude-bridge` стоит `MAX_CONCURRENT=1` — фоновые вызовы толкались бы с
рабочей очередью. Дедуп гоняем вручную пакетом, когда нужно.

**Почему облако выключено.** Сервер самохостится, часть проектов
конфиденциальна. Выгрузка памяти во внешнее хранилище — отдельное решение,
которое никто не принимал.

## Критерий пробы — проверить через месяц, 18.09.2026

**Проба засчитана, если** запрос по теме отдаёт актуальную частоту фразы
с датой замера и историю её изменений — быстрее и надёжнее, чем `grep` по
CSV, и при повторном замере старое значение не затирается, а образует
цепочку версий.

**Проба провалена, если** приходится всё равно лезть в CSV, либо поиск не
находит факт из-за словоформы, либо база требует ручного обслуживания
чаще раза в месяц.

Провалена — сносим: `rm -rf /root/seo/.memora /root/seo/.memora-venv` и
`claude mcp remove --scope user memora-seo`. Потеряли вечер, знание осталось в CSV.

## Известное ограничение

TF-IDF ищет лексически и **не склоняет**. Проверено сразу: запрос
«отраслевые страницы» факт не находит, «отраслевых страниц» — находит.
Для реестра точных фраз это терпимо, для вопросов своими словами — нет.

**Апгрейд, если проба пройдёт:** отдать эмбеддинги локальной модели
`Xenova/paraphrase-multilingual-MiniLM-L12-v2` — той же, что уже работает
в vecmory. Наружу vecmory их не отдаёт (только `/recall` и `/remember`),
поэтому потребуется маленькая прослойка с OpenAI-совместимым эндпоинтом,
на который смотрит `MEMORA_EMBEDDING_BASE_URL`. Ставить рядом torch и
sentence-transformers ради пробы не стали.

## Полезные команды

```bash
cd /root/seo && source .memora/env.sh

# поиск
.memora-venv/bin/python -c "
import sys; sys.path.insert(0,'/root/seo/.memora-venv/lib/python3.12/site-packages')
from memora import storage
c=storage.connect()
for it in storage.hybrid_search(c,'реестр отечественного по',top_k=3):
    print(round(it['score'],2), it['memory']['content'][:120])"

# дозагрузка после нового замера
.memora-venv/bin/python .memora/zagruzit-zamery.py
```
